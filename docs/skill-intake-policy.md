# Skill Intake Policy

Do not turn the repository into a skill dump. Add a skill only when it improves a frequent workflow and has a clear trigger.

## Intake checklist

Before adding a skill, answer:

- What recurring task does it improve?
- What precise trigger should activate it?
- Is it core, language-specific or vendor-specific?
- Does it duplicate an existing skill?
- Does it increase the Codex skill budget significantly?
- Can it be tested with an example task?
- Does it belong in this repo or in a language-specific repo?

## Classification

| Type | Location |
| --- | --- |
| Core workflow | core repo |
| Language-specific | language repo |
| Vendor-specific | vendor adapter or docs |
| One-off task | command or template, not skill |

## Default decision

When unsure, document the pattern first. Add a skill only after it repeats.
