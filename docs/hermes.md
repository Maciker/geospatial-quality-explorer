# Hermes Agent setup

[Hermes Agent](https://hermes-agent.nousresearch.com) (Nous Research) is an OpenAI-compatible agent that
consumes [agentskills.io](https://agentskills.io) skills and `AGENTS.md` project context natively. This
repository's canonical `.ai/skills` and `AGENTS.md` already match those formats, so the Hermes vendor adapter
projects them as-is into `.hermes/`.

Generated by `pnpm ai:sync` (see [vendor sync](./vendor-sync.md)). Do not edit `.hermes/` by hand.

## Generated layout

```text
.hermes/
├── config.yaml   # secret-free model/provider + external skills dir + terminal backend
├── skills/       # agentskills.io skills projected from .ai/skills
├── AGENTS.md     # copy of the root instruction contract (project context)
└── README.md     # adapter notes
```

## Install the skills

Two supported paths, both backed by the same projected `.hermes/skills` directory.

### As a tap (publishable, shareable)

```bash
hermes skills tap add maciker/agent-workflow-code-ts
```

A tap is just a GitHub repository that is a directory of `SKILL.md` files. The skills then appear in the
system-prompt index, `skills_list`, `skill_view`, and as `/<skill-name>` slash commands.

### As a local external directory

Point Hermes at the projected directory in `~/.hermes/config.yaml`:

```yaml
skills:
  config:
    agent_workflow:
      path: ./.hermes/skills
```

If the same skill name exists locally and in an external dir, the local copy wins.

## Configure the model provider

Set the provider and model in `config.yaml` or with `hermes model <provider:model>`. Hermes connects to any
OpenAI-compatible endpoint — Nous Portal, OpenRouter, OpenAI, NVIDIA NIM, or your own `base_url`.

```yaml
model:
  default: Hermes-4-405B
  provider: nous                    # nous | openrouter | openai | anthropic | custom
  base_url: "https://inference-api.nousresearch.com/v1"
  api_key: "${NOUS_API_KEY}"
  api_mode: chat_completions        # chat_completions | codex_responses | anthropic_messages
```

**Secrets never go in `config.yaml` or the repository.** Put API keys in `~/.hermes/.env`:

```env
NOUS_API_KEY=...
```

## Cross-model QA on Hermes

This repository requires cross-model QA: the model that reviews a change must differ from the model that
implemented it (see `AGENTS.md` and the `qa-cross-model` skill). Hermes makes this a one-line switch — run the
implementation turn on one `provider:model`, then re-run the `qa-cross-model` skill after switching the model
block (or `hermes model <other-provider:model>`).

## Optional: Hermes-specific skill metadata

Skills are projected unchanged because the agentskills.io `name`/`description` frontmatter is sufficient. If you
later want richer Hermes integration (tags, category, credential prompts), add a `metadata.hermes` block to the
canonical `.ai/skills/<skill>/SKILL.md` and regenerate — it is ignored by other vendors:

```yaml
metadata:
  hermes:
    tags: [tdd, architecture]
    category: engineering
```
