# Triage

Input: $ARGUMENTS (issue, PR or requested backlog scope).

Read the full request, comments and existing labels; for a PR read the diff too. Check whether the requested behavior already exists, overlaps another issue, or contradicts a recorded decision. Reproduce bug claims where the available environment permits.

Report the category, evidence, missing information, dependencies and readiness for agent work. Ready means the outcome is observable, scope bounded, required access available and blockers resolved. Unverified claims remain unverified.

Use the existing tracker vocabulary. Without configured labels, describe readiness in the local report rather than creating labels. Write the proposed agent brief using `.ai/templates/tasks/ticket.md`; separate facts from assumptions. Modify labels, post comments, close requests or contact reporters only within an explicitly authorized action. A duplicate implementation is different from a rejected product idea.
