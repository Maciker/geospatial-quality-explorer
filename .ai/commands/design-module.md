# Design Module

Input: $ARGUMENTS (module, caller pain or architectural question).

Use `codebase-design` and existing architecture rules. Trace real callers and compare two materially different interfaces, including usage, invariants, errors, dependencies, test surface and migration cost. Preserve domain vocabulary with `domain-modeling` where needed.

Write the comparison and recommendation to `.ai/workspace/tasks/<task-id>/design.md`. For a survey request, rank evidenced candidates before designing one. No production edits follow until covered by the approved implementation scope.
