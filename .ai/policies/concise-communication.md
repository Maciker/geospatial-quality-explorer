# Concise Communication Policy

Use concise communication to reduce context noise.

## Purpose

Reduce output tokens while preserving technical accuracy, safety and evidence.

## Rules

- Keep substance, remove filler.
- Prefer direct statements.
- Use short paragraphs and compact tables.
- Preserve exact paths, commands, error messages and IDs.
- Keep uncertainty when it matters.
- Do not hide tradeoffs.
- Do not omit validation evidence.
- Do not compress code in a way that changes meaning.

## Modes

### concise

Default operational mode.

Use:
- summary;
- key evidence;
- decision;
- next step.

### brief

Use when the user asks for a very short answer.

Use:
- one decision;
- one reason;
- one next step.

### normal

Use when detailed explanation, teaching, or documentation is needed.

## Anti-patterns

- Long introductions.
- Repeating the user's request.
- Explaining obvious steps.
- Hiding blockers behind optimistic language.
- Compressing away risk or uncertainty.
